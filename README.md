# 寝室管家——三机分布式宿舍测控系统

## 1. 项目概述

本项目面向学生宿舍环境信息分散、设备控制不便以及安防状态难以及时获取等问题，设计并实现了一套由三块 STC15F2K60S2 单片机和 PC 上位机构成的分布式测控系统。

系统以 NodeA 为主控网关，通过 RS-485 现场总线轮询 NodeB 环境节点和 NodeC 安防节点；PC 上位机通过 USB 串口与 NodeA 交换数据，并向电脑或手机浏览器提供实时监测、设备控制、历史分析、事件追溯、通信诊断和自然语言交互功能。

本仓库同时包含三节点固件、FastAPI 后端、Vue 3 前端及测试工具，可在无硬件的模拟模式下运行，也可接入三块开发板进行真实串口联调。

## 2. 系统总体架构

```text
电脑/手机浏览器
        ⇅ HTTP / WebSocket
PC 上位机（Vue 3 + FastAPI + SQLite）
        ⇅ USB 串口
NodeA 主控网关
        ⇅ RS-485 半双工总线
  ┌───────────────┐
  ⇅               ⇅
NodeB 环境节点   NodeC 安防节点
```

各节点职责如下：

| 节点 | 总线角色 | 主要职责 |
|---|---|---|
| NodeA 主控网关 | RS-485 主站 | 本地显示与按键输入、实时时钟、参数存储、从站轮询、命令转发、状态汇总及 PC 串口通信 |
| NodeB 环境节点 | 地址 `0x02` 的从站 | NTC 温度采集、光照等级采集、风扇 PWM 控制和步进电机通风窗控制 |
| NodeC 安防节点 | 地址 `0x03` 的从站 | 门磁与振动检测、超声波测距、布防状态机、报警提示和步进电机锁舌控制 |

三节点采用主站轮询、从站应答的通信方式，数据帧使用 CRC16/Modbus 校验。控制命令由 PC 下发至 NodeA，再由 NodeA 转发至目标从站；设备状态、事件及执行回执沿相反方向返回。

## 3. 主要功能

### 3.1 环境与安防监测

- 实时显示温度、光照等级、门口距离、门磁、振动、布防、报警及节点在线状态。
- 根据温度阈值自动调节风扇 PWM 输出，并支持手动模式。
- 根据环境条件和控制命令驱动通风窗。
- 支持布防、撤防、接近阈值设置、报警静音和锁舌状态管理。
- 对 NodeA、NodeB、NodeC 的在线状态、轮询超时及 CRC 错误进行诊断。

### 3.2 PC 上位机

- 使用 Vue 3 构建响应式界面，可在电脑和手机浏览器中访问。
- 使用 WebSocket 推送实时状态，避免频繁手动刷新。
- 使用 SQLite 保存遥测、事件、命令和参数，支持历史曲线与事件追溯。
- 为每条控制命令记录 `pending`、`confirmed`、`failed` 或 `timeout` 状态。
- 提供模拟设备模式，可在不连接开发板时演示主要功能和故障场景。

### 3.3 Agent 工具调用

配置兼容 OpenAI function calling 的模型服务后，可使用自然语言查询实时状态和历史数据，也可发起风扇、阈值、布防等控制请求。模型只负责选择工具和生成结构化参数，实际参数校验、命令下发和结果判定均由后端完成。

布防、撤防和报警静音等敏感操作必须经过用户二次确认。系统只有在收到设备回执后才报告执行成功，模型生成的自然语言不作为执行成功的依据。未配置模型服务时，除 Agent 页面外的功能不受影响。

## 4. 设计特点

1. **分布式节点设计**：环境采集、安防检测与主控通信分别运行，降低单个程序的任务复杂度。
2. **上下行闭环**：控制命令、节点应答和执行回执形成完整链路，串口写入成功不等同于设备执行成功。
3. **状态可信性处理**：节点离线或数据过期后，相应字段置为“未知”，不使用旧值冒充实时状态。
4. **通信容错**：后端能够处理串口数据的粘包、拆包和噪声前缀，并支持断线检测与自动重连。
5. **数据可追溯**：遥测、报警事件和控制命令统一写入数据库，便于查询和复核。
6. **软硬件双模式**：模拟模式便于独立演示和软件测试，真实串口模式用于三节点联调。

为避免超出硬件能力，界面对物理量采用保守表述：光敏结果称为“光照等级”而非照度值；风扇显示 PWM 输出而非实测转速；通风窗和锁舌显示从板保存的软件状态，不等同于机械位置反馈。

## 5. 运行方法

### 5.1 环境要求

- Windows 10/11
- Python 3.11 或更高版本
- 运行已构建的前端不需要安装 Node.js
- 重新构建前端时需要 Node.js 和 npm
- 重新编译、烧录固件时需要 Keil C51 和 STC-ISP

### 5.2 首次安装

在项目根目录双击 `setup.cmd`。脚本会依次创建 `.venv` 虚拟环境、安装 Python 依赖、由 `backend/.env.example` 生成 `backend/.env`，随后启动服务并打开浏览器。

安装完成后访问：

- 本机：<http://localhost:8000>
- 同一局域网内的手机：`http://电脑的IPv4地址:8000`
- 后端接口文档：<http://localhost:8000/docs>

手机访问前应确保电脑与手机连接同一局域网，并允许防火墙放行 TCP 8000 端口。

### 5.3 后续启动

- 双击 `启动寝室管家.cmd`：启动后台服务并打开网页。

### 5.4 模拟模式

首次安装生成的配置默认使用模拟模式，无需连接硬件：

```ini
DEVICE_MODE=mock
```

模拟模式可验证实时页面、历史曲线、控制流程、报警事件、命令回执及节点离线等功能，适合工程检查和软件演示。

### 5.5 真实串口模式

将 PC 连接至 NodeA 的 USB 串口，并在 `backend/.env` 中修改：

```ini
DEVICE_MODE=serial
SERIAL_PORT=COM3
SERIAL_BAUD=9600
```

其中 `COM3` 应替换为设备管理器中 CH340 对应的实际端口。NodeA、NodeB 和 NodeC 之间通过 RS-485 的 A、B、GND 共地连接。修改配置后重新启动后端即可。

### 5.6 Agent 配置（可选）

在 `backend/.env` 中填写模型服务参数：

```ini
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
```

密钥仅保存在本机的 `backend/.env` 中，该文件已被 `.gitignore` 排除，不应提交或公开。

## 6. 固件编译与烧录

三套 Keil 工程位于：

```text
firmware/NodeA_主控网关/
firmware/NodeB_环境节点/
firmware/NodeC_安防节点/
```

各节点 `output/` 目录中已提供对应的 HEX 文件，可直接使用 STC-ISP 烧录。如需重新编译，可打开相应的 `.uvproj` 工程并执行 Build。

烧录参数：

| 项目 | 设置 |
|---|---|
| 单片机型号 | `STC15F2K60S2` |
| IRC 频率 | `11.0592 MHz` |
| 程序文件 | 对应节点 `output/` 目录中的 HEX 文件 |

当上位机正在使用串口时，烧录前双击 `烧录前-释放串口.cmd`，使后端释放串口但保持网页服务运行；烧录完成后可等待系统自动恢复，也可双击 `烧录后-恢复串口.cmd`。STC-ISP 应先点击“下载/编程”，再重新给开发板上电以完成冷启动握手。

## 7. 工程结构

```text
firmware/       NodeA、NodeB、NodeC 的 Keil C51 工程及 HEX 文件
backend/        FastAPI 服务、设备层、通信协议、SQLite 与 Agent 工具
frontend/       Vue 3 前端源码及已构建的 dist 文件
tools/          串口管理、启动和真实硬件验收工具
docs/           验收记录与真实硬件异常验收说明
```

数据库默认位于 `backend/data/dorm.db`，首次启动时自动创建。默认每秒最多保存一条遥测数据，并清理超过 14 天的遥测记录。

## 9. 已知边界

- 风扇没有转速传感器，系统只能确认 PWM 输出值。
- 通风窗和锁舌没有限位或位置传感器，系统只能确认从板的软件状态和命令回执。
- 光敏采集结果为基于 ADC 阈值划分的 0～4 级，不表示经过标定的 lux 值。
- 三节点通信采用单主站轮询方式，NodeB 和 NodeC 不主动占用 RS-485 总线。
- Agent 功能依赖外部模型服务和网络；模型不可用时，监测、控制、数据库与前端功能仍可独立运行。
