# 真实硬件异常验收

这套验收用于检查三板系统在断线、接线错误和命令无回执时是否如实显示状态，避免把旧数据或“请求已发送”误当成“设备已执行”。验收工具会读取上位机公开 API、发送少量离线验证命令，并把每一步的结果和证据保存成 Markdown、JSON 两份报告。

## 开始前

1. 三块板按正常方式连接并烧录最新的 NodeA、NodeB、NodeC 固件。
2. `backend/.env` 使用 `DEVICE_MODE=serial`，串口号为 NodeA 的 CH340 端口，波特率为 9600。
3. 双击 `启动寝室管家.cmd`，确认网页中 A/B/C 三个节点均在线。
4. 双击项目根目录的 `真实硬件异常验收.cmd`，按照窗口提示操作。

报告保存在项目的 `artifacts/` 目录。该目录是本机测试证据，不提交 Git。

## 验收范围

| 场景 | 自动判断内容 | 正确结果 |
|---|---|---|
| NodeB 断线 | 在线标志、环境字段、离线命令回执、恢复 | B 离线；温度、光照、风扇和通风窗变“未知”；命令为 `failed/timeout`；复接后上线 |
| NodeC 断线 | 在线标志、安防字段、离线命令回执、恢复 | C 离线；距离、门磁、布防、报警和锁舌变“未知”；命令为 `failed/timeout`；复接后上线 |
| NodeA USB 断线 | 串口与三节点状态、离线命令、自动重连 | 链路和三节点离线；命令不成功；插回后后端无需重启即可恢复 |
| RS485 A/B 对调 | 从站状态、CRC/坏帧诊断、接线恢复 | B/C 至少一个离线且不保留旧数据；可能出现 CRC/坏帧增长；恢复接线后重新上线 |

## 安全与判定说明

- 改动 RS485 A/B 接线前必须先关闭三块板电源，禁止带电插拔或短接电源端子。
- A/B 对调有时产生坏帧，有时只是完全静默。因此“CRC 计数没有增长”本身不能判定故障处理失败；从站离线、读数作废和不误报命令成功才是硬性条件。
- 命令只有收到目标节点匹配回执后才能是 `confirmed`。`failed` 或 `timeout` 都表示系统没有虚构执行成功。
- 工具不能代替操作者完成拔线和接线，也不能伪造“已做真机测试”。报告只记录本次实际完成的步骤。
