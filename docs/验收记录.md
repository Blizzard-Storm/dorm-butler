## 三、开发过程中实测发现并修复的问题

| 问题 | 现象 | 原因 | 修复 |
|---|---|---|---|
| 页面白屏 | 控制台报 `Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of "text/plain"` | Windows 注册表把 `.js` 登记为 `text/plain`，Python `mimetypes` 读注册表后 StaticFiles 用了错误 MIME | `main.py` 启动时 `mimetypes.add_type("application/javascript", ".js")` |
| 表单改不动 | 控制页的模式、阈值输入框每秒被重置 | 1Hz 状态推送无条件覆盖本地表单值 | 引入 `touched` 标记，用户动过的控件不再被服务端值覆盖，提交后交还控制权 |

第二个问题是**浏览器实测才暴露的**——单测和接口测试都发现不了，因为它只在"用户正在编辑"与"状态推送"并发时出现。

## 四、需要上板确认的事项清单

项目已提供交互式验收工具 `真实硬件异常验收.cmd`，会逐项提示物理操作、
自动读取 API 判定结果，并在 `artifacts/` 生成 Markdown/JSON 证据报告。
下列项目仍必须由操作者接上真实硬件后执行，不能用软件单测冒充。

以下事项无法在纯软件环境验证，接上硬件后须逐条确认：

1. **NodeA 串口号**：设备管理器里确认 CH340 对应的 COM 口，填进 `backend/.env`
2. **报文格式一致性**：实际收到的行是否严格 43 字节、字段偏移与 `RepTmpl` 一致
3. **`USE_REPORT` 是否开启**：若被关掉则完全收不到数据
4. **行间隔**：实测是否稳定在 1s 附近，串口忙导致的跳行频率有多高
5. **CRC 错误增长率**：长跑 30 分钟，`E` 字段应保持 000
6. **拔线恢复**：拔掉 USB 后页面应在 5s 内标 NodeA 离线，插回后 2s 内自动恢复
7. **从站掉线**：拔掉节点B 的 485 线，`O` 字段应变 `01`，页面温度立刻显示"未知"
8. **下行通道**：依次验证参数、风扇、通风窗与静音；只有收到目标从站的匹配 ACK 才应显示 `confirmed`
9. **详细状态**：确认页面能显示门磁、布防状态、通风窗/锁舌软件状态，拔线后 3~5s 内变为“未知”
10. **性能诊断**：NodeA 主循环应大于等于 1000 次/秒，三节点 `PollingMisses` 正常应为 0

## 五、当前限制（如实记录，非缺陷）

- **执行器没有物理位置/转速反馈**。风扇、通风窗和静音已有 `FUNC_ACT` 回执闭环，
  但风扇只能确认 PWM 输出，通风窗只能确认从板的软件位置状态，不能表述为实测转速或物理限位确认。
- **AI 助手未实测**。缺 API 密钥，只验证了"未配置时优雅降级"这条路径。
- **原始 ADC 仍不在 NodeA 汇总报文中**。它们只用于 NodeB 单板标定，三板组网模式下显示“未知”。
  门磁、布防、通风窗、锁舌、计数器和各节点 `PollingMisses` 已由 `STA` 报文补齐。
- **光敏只完成分档标定，不是照度计**。`LUX_TH0~TH3` 已按本板 ADC 动态范围标定，
  前端仍称“光照等级 0-4”，不把等级虚构成 lux。
