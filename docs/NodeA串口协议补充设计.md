# NodeA 与 PC 串口协议（已实现）

> 本文档以 `firmware/NodeA_主控网关/source/main.c` 和
> `backend/app/protocol/report.py` 的当前代码为准。

## 1. 链路与串口参数

NodeA 通过 Uart1/USB 与 PC 通信，参数为 `9600, 8, N, 1`。
PC 只直连 NodeA；NodeB/NodeC 的状态和命令由 NodeA 通过 RS485 转发。

## 2. NodeA 上行报文

### 2.1 主遥测报文

```text
[HH:MM:SS] T±ttt Lx Ffff Dddd Ax Obc Eeee\r\n
```

共 43 字节，包含板上时间、温度、光照等级、风扇 PWM、距离、
报警等级、B/C 在线位和 CRC 错误计数。从站离线时，后端必须作废
对应的旧读数；距离小于等于 1 表示无有效回波。

### 2.2 详细状态与性能报文

```text
STA BF=000 BP=000 CF=000 CS=0 V=000 D=000 CP=000 AP=000 L=00000 RB=0 RC=0\r\n
```

| 字段 | 含义 |
|---|---|
| `BF` / `CF` | NodeB / NodeC 状态位，用于窗户、门磁、接近、锁舌等状态 |
| `BP` / `CP` / `AP` | NodeB / NodeC / NodeA 的 `PollingMisses` |
| `CS` | NodeC 安防状态机：0 撤防、1 倒计时、2 布防、3 报警 |
| `V` / `D` | 有效振动和开门累计次数 |
| `L` | NodeA 每秒主循环数，饱和到 65535 |
| `RB` / `RC` | NodeA 对 B/C 的当前连续无应答次数 |

`STA` 与整秒的主报文错开发送。后端只采信 3 秒内的状态，
超时后立即显示“未知”。

### 2.3 板上参数报文

```text
CFG T=28 A=0 H=07 M=00 N=060\r\n
```

用于让网页以板子实际保存的温度阈值、布防状态、闹钟和接近阈值为准。

## 3. PC 下行命令

PC 发送 10 字节定长二进制帧：

| 偏移 | 字段 |
|---|---|
| 0 | 帧头 `0xAA` |
| 1 | `seq`（1~255，0 保留） |
| 2 | 目标标识 |
| 3 | 功能码 |
| 4~7 | `arg0..arg3` |
| 8~9 | CRC16/Modbus，低字节在前 |

`FUNC_SETCFG` 用 `arg0=Cfg 下标、arg1=参数值`；`FUNC_ACT` 用
`arg0=从站序号（0 为 NodeB，1 为 NodeC）、arg1=动作值`。
当前支持温度/接近阈值、布防/撤防、闹钟、PC 对时、风扇手动/自动、
通风窗开/关/自动和报警静音。执行器动作由 NodeA 转发，并等待从站应答。

## 4. NodeA 回执

```text
ACK s=012 t=01 r=00 d=000\r\n
```

| `r` | 含义 |
|---|---|
| 00 | 已生效，或从站已确认 |
| 01 | 参数越界 |
| 02 | 从站离线，参数已缓存但未确认执行 |
| 03 | 从站未在超时内确认 |
| 04 | 不支持的功能码 |

后端只能在 `seq` 匹配且 `r=00` 时把命令标为 `confirmed`。
成功写入串口不等于设备已执行。

## 5. 验收要求

1. 三块板与 `firmware/_主机自测/inc/protocol.h` 的四份协议文件 MD5 必须一致。
2. NodeA、NodeB、NodeC 的 `PollingMisses` 在正常运行时应为 0。
3. NodeA 主循环应不低于 1000 次/秒；连续无应答数长期不得增长。
4. 拔掉某从站后，对应数据和状态必须变为“未知”。
5. 无匹配 ACK 的命令不得显示为执行成功。
