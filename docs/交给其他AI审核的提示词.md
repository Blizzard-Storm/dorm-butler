## 一、项目是什么

「寝室管家」——湖南大学《系统编程与创新设计》课程大作业的 PC 上位机部分。

硬件是三块 STC-B 学习板（主控 STC15F2K60S2），用 RS485 组成主从总线：

```
手机/电脑网页 ──HTTP/WebSocket──> PC 后台 ──USB串口──> NodeA ──RS485──> NodeB / NodeC
```

- **NodeA**（地址 0x01，主站/网关）：数码管人机界面、DS1302 时钟、M24C02 参数存储、
  485 主站轮询、通过 USB 串口向 PC 上报
- **NodeB**（0x02，环境节点）：NTC 测温、光敏分档、PWM 风扇调速、步进电机通风窗
- **NodeC**（0x03，安防节点）：霍尔门磁、振动传感器、超声波测距、布防状态机、电子锁舌

PC 是网络与串口网关，手机不直接连单片机。

## 三、必须先理解的硬约束（这些是核对过源码的事实，不是猜测）

**1. NodeA 当前没有串口下行通道。**
`NodeA_主控网关/source/main.c` 全文没有 `SetUart1Rxd()` 调用，也没有注册
`enumEventUart1Rxd` 回调，只有一处 `Uart1Print()`。也就是说 NodeA 只发不收。

因此接真实硬件时（`DEVICE_MODE=serial`）本系统是**只读监控**：
实时数据、曲线、事件全部正常，但所有控制按钮必须置灰并说明原因。

⚠️ 这是设计约束，不是 bug。**不要**通过"往串口写命令然后假装成功"来"修复"它。
交接要求里明确禁止把"成功写入串口"当作"设备已执行"。
要打通控制必须改固件，方案已写在 `docs/NodeA串口协议补充设计.md`。

**2. 上行报文格式（固件 `RepTmpl` 逐位填数，偏移固定）：**

```
[HH:MM:SS] T±ttt Lx Ffff Dddd Ax Obc Eeee\r\n     共 43 字节，9600/8/N/1
```

偏移：`1,2`时 `4,5`分 `7,8`秒；`12`温度符号 `13-15`温度×10；`18`光照档0-4；
`21-23`风扇占空比；`26-28`距离cm；`31`报警等级0/1/2；`34`节点B在线 `35`节点C在线；
`38-40`CRC累计错误数。

**3. 报文是有损的。** 485 总线上跑的 12 字节数据区里，以下内容**没有**进入串口报文：
门开关状态、布防状态机、振动/开门次数、通风窗开合、锁舌状态、原始 ADC、各节点 PollMiss。
这些字段在 serial 模式下必须保持 `None`（前端显示"未知"），不能编。

**4. 物理量必须如实描述**（课程交接文档的明确要求）：
- 光敏电阻**未标定**，只能叫"光照等级 0-4"或"光照 ADC"，**不得**说成 lux
- 没有转速传感器，只能叫"风扇 PWM 输出"，**不得**说成实测转速
- 通风窗和门锁**没有位置反馈**，只能显示"软件状态"，不得声称机械位置已确认
- 超声波无有效回波时显示未知；固件把无效值 -1 钳成了 000，且 `DIST_MIN=2`，
  所以报文里 `D000` / `D001` 一律是无效读数，不是"0cm 有人贴门"
- 从站离线时 NodeA 上报的是**上一次的陈旧值**，必须作废，不能当实时读数显示

**5. 固件侧的坑（如果你要改固件才需要关心）：**
- 学校的 Keil 是 **Eval 版，用户代码上限 2048 字节**，超了直接
  `FATAL ERROR L250` 不生成 hex。NodeA 已经为压体积做了四处结构性改写，
  加代码前先看链接输出里 `USED: xxxxH BYTE (yy%)` 那一行
- 固件 `.c` 文件是 **GBK 编码**，`inc/` 里的头文件是 UTF-8。
  **不要**批量转码，会导致中文注释乱码或 Keil 编译异常
- `protocol.h` 是三块板共用的唯一真相源，`backend/app/protocol/frames.py`
  是它的 Python 镜像。改任何一边都必须同步另一边，并跑 `pytest`
